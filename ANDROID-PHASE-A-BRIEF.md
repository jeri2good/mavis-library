# Phase A — Web + backend prep for the Mavis Library Android app

Repo: this directory (clone of jeri2good/mavis-library, v0.4.0, branch main). Full product spec: `docs/ANDROID-PRD.md` (read it first; sections 5, 6 and 9 are your scope).
You are the ONLY writer in this tree. Work on a new git branch `android`. Commit locally in small steps. Do NOT push. Do NOT touch anything outside this directory.

## Hard rules
- NO secrets anywhere. Never read, print, write or commit API keys. Keys live in Netlify env vars only.
- Browser/Netlify behaviour must stay IDENTICAL. `npm run build` output for the web must be unchanged in behaviour.
- Existing suites must still pass: `npm run test:functions` (baseline green) and, if runnable here, `npm run test:e2e` (65 browser checks). Report honestly which you could not run.
- Report blockers honestly. Never fabricate output. Exit codes prove nothing; show real command output in your receipt.
- After EACH numbered task: run `npm run test:functions`, then append a line to `PROGRESS.md` (task, files, test result).
- At the end ALWAYS write `RECEIPT.md` (what changed, exact files, test output, what was NOT done) even if you fail or stop early.

## Tasks (all from PRD section 5 / 9)
1. `src/lib/native.js`: export `isNativeApp()` = `!!(window.Capacitor && window.Capacitor.isNativePlatform && window.Capacitor.isNativePlatform())`.
2. `src/lib/api.js`: export `apiUrl(path)`. Returns `path` unchanged unless `import.meta.env.VITE_API_BASE` is set, then returns `VITE_API_BASE + path`. Replace EVERY relative `/api/...` call site in `src/` (fetch calls, `<audio src>`, cover `<img src>`, `?motion=` and `?picture=` polling URLs, EventSource/URL builders). Find them all with grep for `/api/` in src and index.html; the PRD says ~38. Leave absolute URLs alone. List every call site you changed in RECEIPT.md.
3. `netlify/lib/cors.mjs`: `withCors(handler)` wrapper. Allowed origins ONLY `https://localhost` and `https://mavis-library.netlify.app`. OPTIONS -> 204 with headers. For allowed origin return `Access-Control-Allow-Origin: <that origin>` (never `*`), `Vary: Origin`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, `Access-Control-Allow-Headers: authorization, content-type, x-mavis-access, x-mavis-kids, x-mavis-source, x-mavis-voice`. Also expose headers the client reads if any (check src). Refused origin: no CORS headers added (and OPTIONS from refused origin -> 403). Apply to the default export of EVERY function in `netlify/functions`. Preserve each function's existing `config` export and existing same-origin/cross-site POST protections (look at how the "wrong code and cross-site posts" test works and keep it passing; the two allowed origins must now be accepted by that check while all other cross-site origins stay refused). Add tests to `tests/functions` for: allowed origin, refused origin, preflight, and that existing cross-site refusal still holds.
4. Android CSP: a build step that, ONLY when building for Android, injects a `<meta http-equiv="Content-Security-Policy">` into the built `index.html`. Equivalent to the netlify.toml policy with `https://mavis-library.netlify.app` added to connect-src, img-src and media-src, `https://localhost` where needed; DROP `frame-ancestors` and `upgrade-insecure-requests`; keep `script-src 'self'`. Implement via `vite.config.js` mode `android` (and an `index.android.html` or transform plugin — your choice, keep one source tree). Add `npm run build:android` = `vite build --mode android --outDir dist-android` with `VITE_API_BASE=https://mavis-library.netlify.app` set in `.env.android` (not secret). Do NOT run `cap sync` (Capacitor is added in Phase B). The normal `npm run build` must be unchanged.
5. `src/lib/groups.js` `inviteLink()`: use fixed origin `https://mavis-library.netlify.app` in both builds (grep for other `location.origin` uses that build shareable links).
6. Service worker / install UI: in the Android build skip the update toast and the install prompt when `isNativeApp()`. Keep the SW registered.
7. `public/.well-known/assetlinks.json` served as `application/json` (add a `[[headers]]` rule in netlify.toml). Use package `com.mavislibrary.app` and PLACEHOLDER fingerprint strings clearly marked `REPLACE_WITH_PLAY_APP_SIGNING_SHA256` and `REPLACE_WITH_UPLOAD_KEY_SHA256`. Do not invent real fingerprints.
8. Public pages `/privacy` and `/delete-account` (static HTML in `public/`, styled like the app, no external assets). Privacy must name every outside service that receives data: OpenAI (AI text and pictures), fal.ai (scene film motion), Fish Audio (voices and cloud read-aloud), Gutenberg, Open Library, LibriVox and Internet Archive (public requests), Netlify (hosting and storage). Describe accounts data (email, salted password hash, synced shelf/progress/notes/plans/vocabulary), encrypted in transit, deletable. Delete page: in-app route Settings > Account > Delete account, plus contact line `CONTACT_EMAIL_PLACEHOLDER` (owner supplies). Read `docs/HANDOFF.md` to keep claims accurate; do not claim anything the code does not do.
9. Report action: new function `netlify/functions/report.mjs` (wrapped with `withCors`, path `/api/report`, same rate-limit/abuse conventions as sibling functions) storing a short note (what, book/passage ref, optional text, timestamp, app version, NO user identifiers beyond what siblings already use) in Netlify Blobs under a `reports` store; returns a confirmation. Size-cap and sanitize input. Add function tests (success, oversize, refused origin). Add a small "Report this" button to AI answers, AI pictures, AI summaries and scene films in `src/` (find where those render: assistant UI, covers/picture, scenefilm, summaries) wired to it, plus a visible "Made with AI" label on AI pictures and films. Keep the UI minimal and consistent with existing styles.
10. Settings "About" line: app version + build number (from package.json / build define) — web build shows version only.

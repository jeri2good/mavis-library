## Goal (J: "Need a way to add tech sites like this https://intheworldofai.com/")
The user pastes a site address (or a feed address) and it becomes a source in the Discover tech feed, next to the built-in chips (AI news / Research papers / Tech front page).
## Facts Hermes verified about the example site (use as the first real test case, and as a one-tap suggestion)
- intheworldofai.com is a beehiiv newsletter behind a Cloudflare challenge: requests with a browser User-Agent get HTTP 403 "Just a moment...", but a feed-reader User-Agent like `Mozilla/5.0 (compatible; Feedbot/1.0)` gets 200. Its homepage HTML has NO <link rel="alternate"> tag; the working post feed is https://rss.beehiiv.com/ai_podcasts/5F2wtaPWzH.xml (118 <item>s, item <link> = https://intheworldofai.com/p/<slug>, RFC-822 pubDate). Its YouTube feed https://www.youtube.com/feeds/videos.xml?channel_id=UC2WmuBuFq6gL08QYG-JjXKw (Atom) also works. /feed, /rss, /rss.xml, /feed.xml all 404. So feed discovery MUST also scan the page for any URL matching rss|feed|atom|\.xml (e.g. rss.beehiiv.com/...), not only <link rel=alternate>.
## Implementation (all ON DEVICE; the app fetches the feeds itself - do NOT send arbitrary user URLs to the Netlify server)
- data/feeds/FeedDiscovery.kt: input = what the user typed (bare domain "intheworldofai.com", http(s) URL, or feed URL). Normalise to https. Steps: (1) fetch it with the feed-reader UA; if the response is already RSS/Atom/RDF XML -> done; (2) else parse the HTML: <link rel="alternate" type="application/rss+xml|atom+xml">, then any href/URL in the page containing rss|feed|atom|.xml (candidates ranked: rss.beehiiv.com, /feed, /rss, .xml first; cap 8 candidates), then common paths (/feed, /rss, /rss.xml, /atom.xml, /feed.xml, /index.xml); (3) validate each candidate by fetching and parsing; return the best one with title + item count + newest item date. YouTube channel/page URLs -> feeds/videos.xml?channel_id= when the id is findable (optional, do it if cheap). Return a typed result: Found(feedUrl, title, items, newest) | NotFound(reason: unreachable / blocked / no feed / not a feed) with human text.
- SSRF/safety for on-device fetching: https only (reject http, file, content, ftp, javascript), resolve the host and REFUSE private/loopback/link-local/CGNAT/.local/.internal addresses and bare IPs, max 3 redirects each re-validated, 2 MB body cap, 10 s timeout, no cookies, no credentials, never send the owner access code or any app header. A pure UrlPolicy object with exhaustive JVM tests (127.0.0.1, 10.x, 192.168.x, 169.254.x, [::1], localhost, 100.64/10, userinfo@host tricks, decimal/hex IPs, http:, redirects to private).
- data/feeds/FeedParser.kt: RSS 2.0, Atom 1.0, RSS 1.0/RDF; XmlPullParser via the SAFE route (no DOCTYPE/ENTITY: reject any DTD outright - note Android's SAX/Xerces security features throw, see data/share/NativeEpubText.kt for the working pattern; use XmlPullParser or the same guard). Map to the existing TechItem (id = stable hash of guid/link, title, url, summary stripped of HTML and clipped ~200 chars, source = feed title, points/comments 0); ONLY keep https item links; newest first; cap 40 items per feed; tolerate CDATA, entities, missing dates.
- data/feeds/FeedStore.kt: DataStore-backed list of user sources (id, name, feedUrl, siteUrl, addedAt, enabled), max 20, dedupe by feedUrl. Repository merges: when the user selects a custom source chip, load that feed (cache 15 min, on-disk or in-memory, offline shows cached with an "offline" note); an extra chip "Mine" shows the merged newest items from all enabled custom sources. Keep the three built-in chips unchanged.

# Native Kids mode adversarial review (branch `native`)

**Verdict: not a device-wide child lock; app-shell navigation is gated, but the reader and Android system surfaces are not fully contained.** This is source review plus JVM tests, not a live exploit demonstration. Severity describes risk to the requested seven-year-old containment goal, not a claim of remote code execution. Paths below are relative to the repository root. The native Kids setting and the web app's separate `kidsMode` setting are different stores.

## Findings

1. **HIGH — EPUB subframes and resource navigation are not covered by the top-frame allow-list.** `native-android/app/src/main/java/com/mavislibrary/app/ui/kids/KidsWebReader.kt:40-48` intercepts requests only to serve assets; `shouldOverrideUrlLoading` rejects disallowed URLs **only if `isForMainFrame`**. `src/views/reader.js:179-210` renders an EPUB into epub.js frames and intercepts some *clicks* on external links there, but shows an "Open link" dialog that creates a `target="_blank"` anchor (`reader.js:1213-1222`); it does not restrict all frame navigation, redirects, image/resource loads, or scripted downloads. `KidsWebReader.kt:67-77` attaches click/hash listeners in the document-start script, not a network/subframe policy. Repro reasoning: tap an external link inside an EPUB, choose Open link, or use an EPUB subframe/resource that navigates without the parent click listener. The native callback does not block non-main-frame navigation; whether this actually opens a new window/external app or remains in an iframe depends on WebView behavior and must be checked on device. **Fix:** enforce an explicit per-frame/subresource policy for untrusted book content; suppress external navigation and popups in Kids mode at the WebView boundary, not only with JavaScript/CSS. Block untrusted schemes and test redirects, EPUB frames, and `_blank` on device.

2. **HIGH — selection/long-press can expose Android actions outside the app; the web share code is still callable.** `KidsWebReader.kt:37-39,70-91` hides `.sel-toolbar`/`.verse-bar` and some buttons but does not disable text selection, long-click, context menus, drag/drop, or Android's text action mode. `src/views/reader.js:325-355,404-409` constructs Share/Copy actions; `src/views/bible.js:208-237,622-655` constructs and handles Share, Ask, picture/video and other actions; `src/lib/quotes.js:21-27` invokes `navigator.share` when available. Repro reasoning: long-press text in the Bible or an EPUB iframe; Android's own Select/Copy/Share/Web search/Look up menu may launch another app even if the app's toolbar is hidden. Hidden controls remain wired, so CSS is not an authorization boundary. WebView action-mode entries and Web Share support are **unverified** without a device. **Fix:** disable/restrict native selection action mode, long-click, drag/drop, and share intents for Kids views; gate the web action handlers by a native Kids capability, not display state.

3. **MED — the native reader loads the full adult web runtime and only restricts its displayed route.** `KidsWebReader.kt:28-51,58-93` loads the same bundled app at `https://localhost/`, injects a pre-router hash/click guard and CSS, but installs no native bridge; the main-frame route allow-list itself is strict (`native-android/app/src/main/java/com/mavislibrary/app/ui/kids/KidsContent.kt:18-28`). The adult router only checks the *web* `isKids()` flag for grown-up routes (`src/main.js:129-139`; `src/lib/kids.js:28,63-79`), which is unrelated to the native DataStore (`KidsPrefs.kt:50-55`). Adult features remain mounted/implemented on the allowed book/Bible page: `src/views/book.js:92-127,154-187` has shelf status and download actions; `src/views/reader.js:601-616,1169-1195` wires Ask Mavis and companion actions; `src/views/bible.js:611-675,766-781` wires Ask, study and sharing. Repro reasoning: the `#status` shelf control and reader assistant buttons are CSS-hidden, not disabled at the handler boundary; an accessibility/DOM path to a hidden action, or an unhidden dialog/control generated later, could trigger adult behavior while the allowed hash remains unchanged. This is not proof that a seven-year-old can invoke those hidden buttons by ordinary touch. **Fix:** introduce a native-to-web, unforgeable Kids capability and remove/disable disallowed handlers/features, including assistant/cloud voice, owner-only calls, shelf mutation and settings-independent dialogs, before rendering. Prefer a minimal child-only reader over CSS filtering the adult runtime.

4. **HIGH — Kids WebView shares the adult web origin/storage, including a cached owner access code.** `native-android/app/src/main/java/com/mavislibrary/app/ui/kids/KidsWebReader.kt:28-31,50-51` and `native-android/app/src/main/java/com/mavislibrary/app/web/WebHost.kt:45-46,125-129` both serve the app at `https://localhost/` with DOM storage enabled (`KidsWebReader.kt:31-35`, `WebHost.kt:150-156`). On the adult path, `MainActivity.kt:58-61` sends the native owner code to `WebHost.kt:193-207`; `src/main.js:282-283` passes it to `src/lib/features.js:47-49`, which persists it in IndexedDB through `src/lib/store.js:239-258`. The child web app calls `loadSettings()` at boot (`src/main.js:215-228`) and `src/lib/features.js:12,18-23,52-59` uses that same cached code for owner requests, only setting the `x-mavis-kids` header when the **web** `kidsMode` preference is true (not when native Kids mode is enabled). Repro reasoning: save an owner code in adult Settings, enter native Kids mode, open a book/Bible passage, then exercise any still-accessible owner feature; normal WebViews in the same app data directory share web-origin storage, so absence of a *new* native bridge in KidsWebReader does not isolate a previously stored secret. The exact in-device availability and feature entry path still need verification. **Fix:** stop storing the owner code in shared web storage, migrate/delete the existing cached value, segregate child browsing into a truly separate origin/profile, and enforce server-side Kids policy independent of the browser's editable setting. Never give the child page an owner credential.

5. **MED — Kids playback shares a remotely controllable, exported media service with the adult app.** `native-android/app/src/main/java/com/mavislibrary/app/ui/kids/KidsRoot.kt:75-77,120-127` stops an adult queue only when connected/playing and the local `kidsAudio` flag is false; `kidsAudio` is `rememberSaveable` at line 51 and is not bound to the actual media item's book key. `native-android/app/src/main/AndroidManifest.xml:43-51` exports `PlaybackService`; `native-android/app/src/main/java/com/mavislibrary/app/audio/PlaybackService.kt:113-119,168-177,201-221` publishes a media session with MainActivity as its session activity and accepts all default player commands and custom sleep/seek commands without a Kids-mode check. `PlaybackController.kt:73-96` plays the selected Kids recording in that same session. Repro reasoning: notification/lock-screen/Bluetooth/another media controller can control the shared queue; a paused adult queue may remain until a child presses Play, and an external controller with a session can potentially change playback while Kids mode is on. Notification tap resolves to MainActivity and should still show Kids UI because `MavisRoot.kt:96-103` gates adult composition; it is **not** evidence of an adult-shell notification bypass. **Fix:** enforce Kids-state and curated-item restrictions in the service/session callback, clear disallowed queues on entry (including paused), and bind UI playback ownership to current media metadata, not a saved Boolean. Verify notification actions with a device.

6. **MED — a 4-digit PIN is a rate-limited convenience gate, not strong authentication.** `KidsPrefs.kt:31-41,49-68,80-84` stores a random 16-byte salt and a single SHA-256 digest; five wrong attempts trigger 30 seconds, persisted in DataStore, but the hash is fast to guess offline if app data is obtained. The lock deadline uses `System.currentTimeMillis` (`KidsPrefs.kt:50,60-68`), so setting the device clock forward can end the wait; no attempt counting across subsequent windows. `KidsSetup.kt:43-51` holds plaintext only in Compose state until start; no plaintext persistence/logging was found in this native path. Repro reasoning: with Settings/time control, advance the clock past a lock deadline; with the app's data file, enumerate 10,000 PINs offline. Merely killing/restarting the process does **not** reset the persisted misses/deadline (covered by the new DataStore recreation test). **Fix:** use a monotonic lockout for a live process plus persisted wall-clock/boot-aware deadline on restart, stronger exponential throttling, and a slow password KDF/longer parent secret if this is intended as a security boundary; do not market the 4-digit PIN as device security.

7. **MED — debug drive intent has no Kids-state check (overlay is gated later by the root).** `MainActivity.kt:52-56,126-136` allows the debug-only `DEBUG_DRIVE` action to set `driveModeActive` and dim the display without checking Kids state; the activity is exported (`AndroidManifest.xml:31-41`). `MavisRoot.kt:96-103` returns KidsRoot **before** the adult DriveModeScreen at line 189, so this code does **not** establish an adult-screen bypass. Repro reasoning: on a debug build, send an explicit intent to exported MainActivity with that action while Kids mode is on; brightness/state still changes, but the Kids composable remains in front. The normal drive monitor is disabled when Kids state loads (`MainActivity.kt:87-89,107-111`). **Fix:** reject debug and monitor drive activations while Kids mode is enabled, including cold-start and `onNewIntent`, and clear already-active state when entering Kids mode; verify brightness on a debug device.

8. **LOW — the native allow-list protects top-level hash routes, not all top-level URL variation or download mechanics.** `KidsContent.kt:19-28` insists on HTTPS, literal `localhost` authority, root path and exactly the selected curated book/read or Bible hash, but never inspects `uri.rawQuery`; `KidsWebReader.kt:40-43` has no explicit download listener, file-chooser override, popup handler, or per-resource URL restriction. `src/views/book.js:192-221` fetches and stores an EPUB in browser storage and includes offsite `target="_blank"` links; the document-start click listener (`KidsWebReader.kt:70-77`) is intended to suppress those anchors. Repro reasoning: a root-page URL with an arbitrary query but the selected hash passes the Kotlin predicate; the currently reviewed router consumes the hash, so no adult route from that alone is proven. Failed downloads generate offsite links, which parent click interception should block but has not been device-tested. **Fix:** require a canonical main-document URL (empty query) and explicitly deny platform download/file/popup surfaces in the child view; verify the failed-download and `target=_blank` paths.

9. **HIGH (scope limitation) — Android system UI can exit the app without the PIN.** `KidsRoot.kt:78-89,130-139` intercepts Compose Back and requires the PIN to set Kids mode off; `MavisRoot.kt:96-103` keeps adult tabs/Settings/Listen uncomposed while the stored flag is true. Neither `KidsRoot.kt` nor `MainActivity.kt` provisions Android lock-task/kiosk mode or a device-policy controller; `AndroidManifest.xml:31-55` only declares the normal launcher/activity/services. Repro reasoning: Home/Recents, notifications/quick settings, split screen, or Settings → App info → Clear storage remain OS surfaces outside this app; clearing app data removes the DataStore and the next launch starts in adult mode. This is **not a PIN bypass inside the app**; it requires access to OS settings or a system affordance. **Fix:** if the requirement is unsupervised, device-wide containment, use supervised Android child account/device policy or managed lock-task plus system restrictions. Otherwise document that Kids mode is in-app only, and require an OS-level parental control for app data/settings.

## Controls confirmed in source

- Native persisted mode is read before adult navigation composes (`MavisRoot.kt:96-103`); Kids Back returns home (`KidsRoot.kt:78-79`). A fresh launch, an ordinary MainActivity intent, or tapping the media session's activity intent does not itself set `enabled=false` (`KidsPrefs.kt:57-71`). No exported deep-link filter into adult Compose routes is declared (`AndroidManifest.xml:31-41`). Settings and native Listen are adult tabs (`MavisRoot.kt:65-71,173-175`) and not composed in Kids mode; Kids Listen uses `PlaybackController` (`KidsRoot.kt:120-127`).
- The native Kids WebView does not call `addJavascriptInterface`, inject the owner code, or register a file picker (`KidsWebReader.kt:27-51`), unlike the adult `WebHost.kt:131-168,193-207,318-330`. `MainActivity.kt:57-61` still creates the adult WebHost and asynchronously loads the owner code even when Kids mode is enabled; its WebView is lazy (`WebHost.kt:144-149`) and is not mounted by KidsRoot. The child view receives no new native code injection, but the adult handoff persists the code on the **shared** web origin (finding 4); lack of a bridge does not isolate web storage. Web/cloud voice paths remain present in the bundled reader as noted above; no evidence of native voice automatically activating from KidsRoot was found.
- PIN checks are atomic DataStore edits (`KidsPrefs.kt:57-71`); the stored PIN value is salt:digest, not plaintext (`KidsPrefs.kt:33-41,55,82-83`). `start()` itself can reset PIN/lockout (`KidsPrefs.kt:52-55`) but its UI caller is Settings (`SettingsScreen.kt:83`), which is absent while Kids mode is enabled; no in-app Clear data action was found. The separate *web-only* Kids PIN is unrelated and does not guard the native view (`src/lib/kids.js:28,59-79`).

## Not determined without a device

- Whether long-press (including inside epub.js iframes), selection toolbar items, drag/drop and Web Share actually expose Search/Web search/Look up/Share or launch an external app on the installed Android System WebView; whether target-blank, `window.open`, redirects, `intent:`/`mailto:` links, file inputs and download URLs invoke Android UI with the current `WebChromeClient` defaults.
- Whether a malicious/odd EPUB navigates an iframe or loads active/external resources despite `allowScriptedContent: false`, and whether `doUpdateVisitedHistory` can visibly display a disallowed top-level fragment before resetting it (`KidsWebReader.kt:40-50`, `reader.js:179-210`). JVM route tests validate the Kotlin predicate, **not** Chromium's callback order or DOM injection.
- Exact notification tap and media-button behavior, including a paused pre-Kids queue, another app's media browser, notification shade/quick settings, system Back versus Home/Recents, split-screen, restricted child accounts, OS-app-info access and process death while audio plays. No emulator or physical device was used.

## Verification

New JVM tests: `app/src/test/java/com/mavislibrary/app/data/kids/KidsPersistenceReviewTest.kt` (new DataStore object over the same disk file after closing the first scope, expiry and hash format) and `app/src/test/java/com/mavislibrary/app/ui/kids/KidsRouteReviewTest.kt` (encoding, uppercase, userinfo/authority, port, path, query, other book, Bible/Listen/Settings). Existing `KidsPrefsTest.kt`, `KidsContentTest.kt` and `NavigationShellTest.kt` cover additional wrapper and Compose behavior. `./gradlew testDebugUnitTest --no-daemon -q` passed with 24 XML suites, **102 tests, 0 failures, 0 errors, 0 skipped** (sum of `app/build/test-results/testDebugUnitTest/TEST-*.xml` suite attributes); five tests are in the two new files. This verifies JVM logic only, not WebView/device behavior.

## Hardening

- Findings 1 and 8: Kids WebView now applies a pure-Kotlin navigation allow-list to main frames and subframes; only the selected `https://localhost/` book/read or Bible route is allowed, with `about:blank`, localhost-origin `blob:` and `data:` admitted only for EPUB subframes. The route requires no URL query or userinfo. Popups, file selection and downloads are disabled; window-opening JavaScript is disabled. Tests cover case/encoding, authority/userinfo/query, allowed EPUB frame schemes and rejected external/active schemes. This is navigation filtering, **not** a blanket subresource firewall: `shouldInterceptRequest` still serves bundled assets and does not block every non-navigation resource request.
- Finding 2: native selection action modes and long-click/haptics are disabled; the document-start script prevents selection/context/drag events, applies nonselectable CSS, and replaces Web Share and `window.open`. This script is registered for the localhost origin; EPUB `blob:`/`data:` frame injection and actual Android WebView behavior remain unverified.
- Finding 4 and part of 3: document-start `fetch` and `XMLHttpRequest` wrappers remove `x-mavis-access` and force `x-mavis-kids: 1` for requests that use those APIs. A JVM script-content test checks the installed wrapper text, **not** network behavior. Adult and Kids views still share the web origin/storage; cached owner credentials have **not** been migrated, deleted or isolated. This is a partial mitigation, not an unforgeable Kids capability or complete fix for findings 3/4; other request APIs and child-frame execution need design and device/network validation.
- Finding 7: MainActivity now defaults to no drive activation until Kids state loads, ignores debug drive intents in Kids mode (including cold start and `onNewIntent`), gates drive-monitor callbacks and clears the active drive state and brightness override on entry. The debug action remains available when Kids mode is off. A Robolectric test exercises the `onNewIntent` brightness path in both modes; cold start and Bluetooth monitor behavior still need device verification.
- Findings 5 (shared media service) and 6 (PIN KDF/lockout): **deferred, needs design**. Finding 9 (Android system UI) remains outside in-app containment.
- Verification after these changes: `./gradlew testDebugUnitTest assembleDebug --no-daemon -q` passed; **25 XML suites, 105 tests, 0 failures, 0 errors, 0 skipped**, read from `app/build/test-results/testDebugUnitTest/TEST-*.xml`. Debug APK assembled. No emulator or physical device was used: EPUB navigation/redirects, popups, file picker, long-press/share, owner-header behavior on real network requests, Read/Listen/Bible/PIN end-to-end behavior, and system UI escape were **not verified**.

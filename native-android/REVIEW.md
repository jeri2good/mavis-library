# Owner-access-code handoff review (232bb8e)

**Verdict: fix needed.** This is source review, not a live WebView exploit test. The navigation policy normally routes external main-frame links to the system browser (`app/src/main/java/com/mavislibrary/app/web/WebHost.kt:61-66,286-290`), but the code handoff itself has no origin check, and it defeats the Keystore-at-rest boundary.

1. **High — unguarded injection into a non-app main document.** `WebHost.kt:187-195,297` evaluates a script containing the plaintext code on every `onPageFinished` and immediately on `setOwnerCode`, regardless of `url` or `webView.url`. `show()` calls `loadUrl()` for the bundled page (`WebHost.kt:197-208`), while `shouldOverrideUrlLoading` only guards navigations delivered through that callback (`WebHost.kt:286-290`); neither that policy nor the origin-scoped document-start *marker* (`WebHost.kt:155-157`) guards the separate owner-code injection. A foreign top-level document reached through an unhandled/app-initiated navigation or redirect could define `window.MavisApp.setAccessCode` and receive the code when `onPageFinished` runs. `evaluateJavascript` targets the top document, not third-party iframes directly; a cross-origin child frame cannot normally read the parent global because of the same-origin policy. **Minimal fix:** before every injection (including the posted UI-thread runnable), parse the current top-level URL and require `WebNavigationPolicy.isAppUrl(Uri.parse(view.url))`; also check `onPageFinished`'s URL against the exact origin before calling the push method. An exact parsed origin check is safer than `startsWith(WEB_ORIGIN)`, which accepts `https://localhost.evil.com/`. Consider a main-frame navigation guard for app-initiated/redirect loads as defense in depth.

2. **High — plaintext persists in web storage after crossing the boundary.** `src/main.js:282-283` exposes `window.MavisApp.setAccessCode` and forwards to `src/lib/features.js:47-49`; `src/lib/store.js:239-258` caches the string in a module-level Map and persists it to the IndexedDB `kv` object store (`src/lib/idb.js:55`). Keystore AES-GCM protects only the native copy (`app/src/main/java/com/mavislibrary/app/data/secure/SecureStore.kt:26-54,93-107`): the injected code is plaintext in browser storage across sessions. `WebHost.kt:192-194` returns early when the native code is cleared, so removing it in native Settings does **not** delete the web copy; the next page load can still use it. **Minimal fix:** use a narrowly scoped native-to-web credential bridge for authorized requests without storing the code in IndexedDB, and explicitly clear any previously stored web `accessCode` when migrating/removing it; at minimum, never persist the native-sourced code and propagate null/blank to clear the web state. Avoid exposing a generic secret-returning JS interface to all frames.

3. **Medium — global is callable by scripts executing in the app document.** `src/main.js:283` creates a mutable `window.MavisApp`; any script running in that document can call/replace its method, and same-origin scripts can read the stored value via `accessCode()` (`src/lib/features.js:12`, `src/lib/store.js:252-258`). The Android CSP uses `script-src 'self'` (`vite.config.js:55-75`, `netlify.toml:29`), which limits remote scripts but does not isolate same-origin scripts, compromised bundled code, or a future XSS. Cross-origin iframes cannot directly read the parent global. **Minimal fix:** keep the credential native-side as in finding 2; an origin check alone does not protect it from scripts on the allowed origin.

**Additional non-security bug found while testing:** `app/src/main/java/com/mavislibrary/app/data/api/MavisApi.kt:80-81` serializes an empty ID list as `ids=`; the server rejects that with a 400 because `netlify/functions/catalog.mjs:19-24` requires at least one numeric ID. `app/src/main/java/com/mavislibrary/app/data/repo/Repositories.kt:29-33` fetches even for an empty shelf, so an empty curated shelf unnecessarily fails instead of returning an empty list. Suggested fix: short-circuit `booksByIds(emptyList())` to an empty result without an API call (or skip the fetch in `SearchViewModel.kt:80-83`). The new edge test records the current serialization; it does not claim the server accepts it.

**Other checks:** `JSONObject.quote(code)` at `WebHost.kt:194` is the right JSON/JavaScript string-literal escaping for quotes, backslashes and control characters; it is not an origin or storage control. The handoff constructs JavaScript source, not a URL, and none of these paths explicitly logs the code or writes it to navigation history (`WebHost.kt:184-208,297-299`). Web requests transmit it in `x-mavis-access` headers (`src/lib/features.js:18-22,53-59`), not in a query string here. Debug builds enable WebView debugging (`WebHost.kt:138`), so attached development tools can inspect the plaintext web state. Static analysis cannot establish every WebView redirect behavior; verify main-frame redirects, external links, iframe isolation and native-code removal on a real device before declaring the handoff safe.
